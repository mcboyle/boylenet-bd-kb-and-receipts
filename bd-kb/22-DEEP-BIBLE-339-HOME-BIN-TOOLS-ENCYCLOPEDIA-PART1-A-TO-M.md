### 1.1 Likely cause of the failure

Byte `0xa0` is a non-breaking space in Latin-1/CP1252 and a stray continuation byte in UTF-8. Two causes are plausible:

1. **A binary file matched the glob.** `head -n 20` on a compiled binary, a zipapp, or a script with an embedded payload emits raw bytes. Position 62666 suggests accumulated output from many files before the offending one.
2. **A script has a legacy-encoded header.** A non-breaking space pasted into a comment, or a Latin-1 author name, would produce the same error.

The wrapper decoded the whole output as strict UTF-8, so one bad byte discarded all of it. The glob is also loose: `bd_[a-m]*` and `bd-[a-m]*` both match non-script artifacts such as `.pyc`, backups, and `.orig` files.

### 2.2 Read headers with the encoding made safe

```bash
for f in bd-[a-m]* bd_[a-m]*; do
  [ -f "$f" ] || continue
  if file -b --mime-type "$f" | grep -q '^text/'; then
    echo "=== $f ==="
    head -n 20 "$f" | iconv -f UTF-8 -t UTF-8 -c
  else
    echo "=== $f === [non-text: $(file -b "$f")]"
  fi
done
```

`iconv -c` drops invalid bytes instead of aborting. For Latin-1 headers, use `iconv -f CP1252 -t UTF-8`. Non-text files are reported by type and never dumped.
